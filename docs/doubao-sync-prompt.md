# 豆包任务提示词 · 记忆同步段

**用法**：豆包的记忆在云端、无本地文件通道，无法用文件约束。把下面这段附在给豆包的任务提示词**末尾**，让它收工时结构化输出"记忆增量"；验收会话（ZCode/Codex/Antigravity）拿到清单后按总库六步管线写入对应项目层——这与现有分工（豆包执行、zcode/codex/antigravity 验收入库）吻合。

## 复制以下内容到豆包提示词末尾

### 收工时追加输出：记忆增量清单

任务全部完成后，除正常交付外，额外输出一节「记忆增量」，固定格式如下（没有的项写"无"，不要编造）：

1. **新事实**：本次确认的、对以后工作有用的事实——每条一句，注明依据（哪个文件/哪次实测）；
2. **新决定**：拍板了什么 + 一句理由；
3. **新的坑**：踩坑记录——现象 + 根因 + 解法各一句；
4. **待办移交**：未完成事项 + 当前状态 + 下一步。

要求：只输出可沉淀的结论，不要过程流水账；每条独立成行、可脱离本次对话独立理解。此清单将被验收方写入记忆总库（`~/memory-bank`）对应项目层，作为跨会话记忆。

**归属标记（2026-10-03 起必填）**：验收方代写时必须标明这些结论是豆包产生的——共享层笔记的 `source` 写成 `conversation:<日期>-doubao-<主题>`，正文首行注明「（<日期> doubao 产出，<验收方> 代写）」，commit 前缀用 `doubao(...)`。原因是 git author 全为同一账号，无法靠 git 归因，只能靠这三处标记。详见全局层 [[memory-attribution-and-sharing-scope]]。
